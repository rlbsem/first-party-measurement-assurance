# Native guard RPC deadline observation

At source [`30cd28c15377e70e8f0733ad1cdba45c123e26f4`](https://github.com/rlbsem/first-party-measurement-assurance/tree/30cd28c15377e70e8f0733ad1cdba45c123e26f4), the native image build and independent digest readback passed. Terraform created 17 bootstrap and all 132 runtime entries. The typed SDK request corrected the preceding Python argument error, but Google rejected the guard's full task readback with `InvalidArgument`: “The deadline cannot be more than 30s in the future.” The configured RPC timeout was 30 seconds. This is an RPC request deadline, not the task's three-hour schedule or its dispatch timeout.

The complete original exception/stack remains private and is hash-bound in [outcome.json](outcome.json). The deeper timing cause is **not established**. Subsequent genuine [read-only probes](rpc-readonly-probes.json) at both 30 and 10 seconds returned the expected HTTP 404 for the exact retired task. That does not reproduce the earlier rejection consistently and does not prove successful arming or an authorization denial.

The runner did not proceed: no Dataflow job, source publication, warehouse query, canary, financial reconciliation, recovery or performance workload started. During retirement, the owner independently observed the exact scheduled task and removed it with HTTP 200 ([record](task-observation.json)). Both model datasets and their bindings were retired before Terraform destroyed the remaining 128 runtime and 17 bootstrap entries. The controller's independent teardown passed; a separate fresh full inventory also established no active owned resources. All three archived generations (source, log and manifest) were independently size/hash verified.

Two buckets remain soft-deleted until November 22 UTC, and two roles remain in deletion grace. Enabled APIs, managed identities and execution history remain. Charges are unavailable; logical absence is not billing clearance. Previous records retain their original bytes.

Current code gives both task RPCs a 10-second deadline with implicit SDK retries disabled. Only the exact observed deadline rejection can cause one additional **read-only** attempt at five seconds; task creation is never repeated. A second rejection, any other invalid request, changed identity or changed schedule still prevents arming. These controls execute in offline tests using the real pinned SDK request serializers and intercepted RPCs. Effective native arming remains unverified.

Google-maintained [client code](https://go.googlesource.com/pkgsite/+/dda8ad47e6f03782c3ad39efdb37e32883c398e1/internal/queue/queue.go) separately notes the Cloud Tasks RPC deadline bound; this is distinct from the documented [task dispatch deadline](https://docs.cloud.google.com/tasks/docs/quotas). The [hash inventory](sha256.json) protects the evidence here.
