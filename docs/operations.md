# Operations and limits

## Reproduce locally

Run from the source checkout with Python 3.12 and `requirements.lock`. Contracts, SQL and web assets resolve relative to this repository; this is an application checkout, not a standalone Python library distribution.

```text
python scripts/verify.py
python -m assurance.server --fixture --workspace .local/projects-v2
```

Verification uses a fresh ignored workspace and explicitly regenerates the checked public evidence and screenshots. The server binds only to loopback. Fixture seeding happens only for a nonexistent database. Restart with the same workspace to preserve synthetic state, or choose another name for a fresh run. There is no automatic reset.

Earlier internal-v1 workspaces are refused without modification. Do not point this version at an old database. [Scenario revision](scenario-revision.md) documents the schema boundary and retained tests.

Standalone commands:

```text
python scripts/demo.py --workspace .local/analytical-example --output .local/example.json
python scripts/browser_verify.py --workspace .local/browser-example
python scripts/package.py --output ../outputs/first-party-measurement-assurance.zip
```

Demo/browser workspaces must be new. The browser runner refreshes actual screenshots and provenance; it requires a current recorded analytical result, normally generated by the full verifier first.

## Operator findings

| Signal | Safe investigation |
|---|---|
| `contract_rejected` | Compare version, fields, types, service and USD policy; do not loosen validation merely to raise acceptance |
| `authority_denied` | Check ingress lane and source stage/reference/project/time/session; browser assertions are not offline authority |
| `identity_conflict` | Same event ID changed; preserve the original and fix the producer |
| `duplicate_conversion` / `duplicate_transaction` | Another ID reused a business fact; verify one economic effect |
| `conversion_conflict` / `transaction_conflict` | Same conversion/payment changed economics; do not bypass with another key |
| `service_rejected` / `value_rejected` | Wrong service or payment items that do not sum in cents |
| `consent_denied` | Stop collection; new permission cannot adopt another source association |
| `time_rejected` | Clock skew or more than seven-day arrival; investigate without rewriting event time |
| Missing financial conversion | Compare eligible signed/payment source and instrumentation; absence alone does not establish cause |
| Value mismatch | Compare signed value with contract conversion or actual payment with purchase; keep the bases separate |
| `not_eligible` | Business fact exists without permitted measurement; do not reconstruct denied tracking |

The health console refreshes on explicit action; it is not a pager service or production SLO monitor. Counts include successful and rejected collector attempts. Browser-suppressed events never enter the receipt ledger. Historical source facts and current permission serve different purposes.

## Delivery and privacy

Browser measurement uses a five-second timeout, three attempts per cycle and short backoff. Exhaustion retains the same envelope only in memory for explicit retry. Reload/revocation clears it, so this design does not promise lossless collection. A real successful response is deliberately discarded by the acknowledgement fault button. Retrying the internal envelope does not push another GTM message.

The independent inquiry endpoint is idempotent by a canonical UUID business request key. It only creates unvalued synthetic inquiries and cannot mutate qualifications, contracts or payments. The trusted offline fixture/adapter is a Python boundary, not an authenticated production connector. No endpoint writes arbitrary source facts.

Host checks, same-origin JSON/custom-header enforcement, request-size limits, CSP, disabled API docs and loopback binding reduce browser-origin misuse. They do not authenticate another local process or provide internet-grade TLS, authorization, rate limits, retention operations or a CMP. Do not expose this app through public hosting or a tunnel. No deployment workflow is included.

Rejected payload bytes and unknown field names are discarded. Admitted history remains after revocation; revocation prevents new collection and is not erasure. A failed remote revocation still requires retry, although the browser stays closed. Public evidence contains fixed synthetic fixture associations and sanitized browser results. Runtime databases, generated session authorities, logs and credentials stay under ignored paths.

## Scope

All scenario values are USD. Opportunities are $50,000-$500,000 by policy; deposits/progress payments may be lower. The fixture spans September inquiries, October proposals and January signatures/payments. It is an exact finite test, not a real operator's sales-cycle distribution.

No real client identities, production connector, causal attribution, verified historical legal consent, cross-device identity, general accounting, refunds, amendments, tax or revenue recognition is implemented. Native Google and GTM execution require separate acceptance: [GTM guide](gtm-implementation.md) and [native runbook](native-google.md).

The package script uses an allowlist, a targeted audit and SHA-256 verification of every ZIP entry. It excludes runtime paths, databases, logs, virtual environments and Git internals. Pattern checks supplement review; they cannot prove arbitrary secrets are impossible.
